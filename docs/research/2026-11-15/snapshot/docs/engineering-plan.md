# Name That LLM 工程规范与实施路线

以下是依据[比赛调研](competition-brief.md)与用户全局工程准则提出的工程设计。当前未实现，不把文档或目录建议当作已具备的能力。目标是先完成可信、可复现的离线提交，再以验证证据决定是否增加模型和资源。

## 开发边界

比赛硬性约束是 Notebook-only、9 小时、离线、合法标签与 Parquet 输出；比赛没有指定本项目必须使用的 linter、测试框架或 Python 版本。后续根据 Kaggle 实际镜像选定兼容版本，先核对一手资料、许可证与维护状况，再固定依赖。当前不新增生产依赖。

优先复用官方基线，不先创建复杂框架、插件系统、服务或全局状态。Notebook 作为可复现交付入口，核心训练、验证和输出逻辑保持职责明确；训练与预测入口分离。公共接口需有类型、输入合同和明确错误；异常不能悄悄变成看似成功的随机标签。

后续建议最小模块边界：数据合同、标签与配置、prompt 分组验证、特征/训练、批量预测、提交验证。只有实现真的需要时才创建对应模块。路径集中配置，输入只读；不递归搜索后随意取第一个 train.csv，避免附加数据集同名文件被误选。

## 验证设计

1. 固定 5 折 prompt 分组，保存 fold 映射、数据哈希与生成配置。先核验每折类别覆盖，不依赖“每个 prompt 必定 18 条”的假设。
2. 每折只用训练部分拟合 TF-IDF、标准化、类别统计、风格规则和校准；禁止先全量拟合再 CV。
3. 主指标为 balanced accuracy；保存 OOF 预测、概率列顺序、每类 recall、混淆矩阵、每折指标和耗时。fold 标准差不是置信区间。
4. 外部数据按来源、prompt、近重复关系做隔离。测试域不同，外部池内验证不能替代官方 held-out prompt 验证。
5. 若外部预计算权重或采样分数使用了全量官方训练文本，不能直接在官方训练折上声称无泄漏 OOF。尤其 Open Pool 的 `match_weight` 需折内重估、在未用于拟合的 holdout 验证，或先不用。
6. 后处理、标点规则、集成权重都算模型的一部分。调参需留出独立 prompt holdout 或嵌套方案；比较同时报告各类收益和退化。统计不确定性应以 prompt 为重采样单位，并区分训练随机性。

主办方允许自动测试文本关系，但隐藏测试没有已知 prompt 分组和等量约束。不要强制每组 18 类各一次，也不要强行让预测类频率均匀。balanced accuracy 对真值类别等权不意味着测试真实先验均匀。

## 可行路线比较

所有成本都是相对判断，尚无本机/本账户实测预算。以下只决定实验顺序，不锁定具体新模型或服务。

| 路线 | 已有直接依据 | 收益与可维护性 | 资源、隐私和失败模式 | 本轮决定 |
| --- | --- | --- | --- | --- |
| A 官方 TF-IDF + 逻辑回归 | 官方 Apache 2.0 Starter，已公开完整代码与 grouped CV | 小、易复现、方便确认数据与提交合同 | CPU 路线；离线处理；可能难区分同家族模型；发布成绩不保证复现一致 | 首先复现，建立可信参照 |
| B 风格特征 + 经审计公开数据 | 公开 CPU 实验和 Open Pool 数据卡 | 有可解释信号，能单独测数据增益 | 标签/路由噪声、来源偏移、全量预计算权重泄漏、CC BY-SA 归属；需固定版本和消融 | 在 A 跑通后逐项实验 |
| C 一个互补 encoder/embedding/LoRA | 社区 Notebook 与关联项目给出具体方法 | 有望区分近似模型，模块化后可独立替换 | GPU、许可证、版本镜像、离线权重、训练成本与跨 prompt 过拟合；更大不保证更好 | 先核验单个模型，增益足够才采用 |
| D 大型多模型 + likelihood 集成 | 社区公开约 40-input pipeline；原始 ATLAS 研究线索 | 多种证据可能互补，但维护与复现难度高 | 多重许可、巨大权重 I/O、9 小时预算、硬件波动、fallback 改变结果；本轮未完整审计 | 不作为起点；仅在简单方案证据不足且预算明确后研究 |

来源详见比赛调研的研究入口。没有默认批准付费 API、自生成数据预算、新框架或依赖；暂不选择 D 的原因是依赖与资源成本尚未审计，而不是断言它不合适。

## 测试驱动与提交检查

行为实现时先写表达需求的失败测试，确认失败原因，再完成最小实现和定向回归；不改金标准、不放宽测试。应覆盖真实合同风险，而不是照抄实现细节：

- 缺列、空文本、非法标签、重复 id、缺失 id、额外 id、id 顺序变更后的正确对齐。
- 多行和不同 batch size；不能以 3 行样例通过替代动态测试规模验证。
- prompt 跨折重叠必须失败；特征拟合不能接触验证折；概率列需与固定标签映射一致。
- 输出 Parquet 可重新读入，schema 和 id 集合与 test 一致，不带多余索引。
- 断网、干净进程、仅挂接声明的资源，从头执行训练/加载/推理/输出；包安装或权重下载不能依赖互联网。

功能完成后再按实际项目入口运行测试、静态检查、凭据扫描和文档检查。现在没有代码、依赖或项目测试命令，不虚构 pytest/lint 成功。

## 资源和复现记录

每次实验记录代码 commit/工作区差异、参数、seed、环境与镜像、输入版本与 SHA-256、fold 映射、指标、训练/推理时长、CPU/GPU/RAM/磁盘峰值。模型和外部来源记录作者、许可、日期、处理步骤与输出哈希。

隐藏重跑的预算应包括导入、模型载入、文件复制、特征提取、推理、后处理和写盘，需留出经实测确定的余量。不得拿小样例 54 秒外推大规模重跑。可评估容量允许下的 `/tmp` staging；没有当前性能证据时不默认复制几百 GB 权重。

如果设计 fallback，必须明确触发条件、完成覆盖、输出合同和日志，并单独验证精度影响；不得静默用多数类替换全部失败。未完成特征、模型缺失或错误标签应尽早报出明确错误。

## 数据和凭据

原始比赛数据、下载模型、凭据、缓存、运行日志与浏览器 traces 不进入公开 Git。未来开始下载时再添加实际目录的忽略规则；本轮只忽略已生成的 `.playwright-mcp/`。

不把测试文本、凭据或 Kaggle token 发给外部 API；不把匿名 id 当可预测的标签特征。公开代码需遵守 Kaggle 共享位置要求；比赛数据的安全条款与来源许可分别检查，不能相互替代。

## 阶段与完成条件

| 阶段 | 产物 | 验收条件 |
| --- | --- | --- |
| 0 数据与环境准备 | 已接受规则后的合法数据、原始哈希与环境清单 | schema/标签/完整性检查；确认本账户硬件与资源；原件不变 |
| 1 基线闭环 | 官方方法的可复现实现、固定 grouped folds、OOF、Notebook | 测试驱动完成关键合同；离线完整运行；Parquet 读回校验；得到自己的 CV 与耗时 |
| 2 数据和风格实验 | 单因素消融、来源/许可审计、折内特征 | 在相同 holdout 上比较；收益不依赖泄漏；记录每类退化与成本 |
| 3 一个互补模型 | 精确版本权重与训练/推理入口 | 完成官方资料/许可证/维护核验；独立对照；GPU 和运行预算可接受 |
| 4 有证据的集成 | OOF 权重/校准、资源明细 | 留出验证确认增益；禁用等量标签假设；端到端压力运行满足 9 小时且有余量 |
| 5 正式提交 | 固定 Notebook version、资源 version、submission 记录 | 复查规则和截止日；先用一次有效提交验证重跑；团队管理每天 5 次额度 |
| 6 最终交付 | 选中的至多 2 版、模型与复现说明 | 截止前完成选择与回读；获奖时按通知提交完整材料 |

获奖复现材料的一般参考是[Winning Model Documentation Guidelines](https://www.kaggle.com/WinningModelDocumentationGuidelines)：README、精确版本 requirements/镜像、集中路径配置、训练/预测命令、模型、目录和资源、方法说明。真正进入交付时再生成，不能现在把模板视为已完成交付。

本轮阶段 0–6 均未执行；完成的是前置公开资料调研与可审查路线。下一步最小动作是合法获取数据并复现 A，具体下载、训练与提交属于后续执行阶段。
